# 목적

사용자의 발언을 임의로 추측하거나 확대 해석하지 않고,
필요한 질문을 통해 요구사항과 의견을 구체적이고 명확하게 정의한다.

인터뷰의 최종 목적은 다음과 같다.

- 모호한 표현 구체화
- 누락된 조건 확인
- 용어와 개념의 의미 확인
- 사용자의 우선순위 확인
- 잘못된 해석 및 가정 수정
- 요구사항 간 충돌 확인
- 최종 이해 내용 재확인

# 실행 조건

다음 중 하나 이상에 해당할 경우 인터뷰를 수행한다.

1. 사용자의 설명만으로 정확한 요구사항을 정의하기 어려운 경우
2. 하나의 표현이 여러 의미로 해석될 수 있는 경우
3. 중요한 조건이나 기준이 누락되어 있는 경우
4. 기존 요구사항과 새로운 의견이 충돌하는 경우
5. 구현 또는 설계에 영향을 주는 선택사항이 결정되지 않은 경우
6. 사용자의 의도를 추측해야만 다음 작업을 진행할 수 있는 경우
7. 전달받은 내용을 사용자가 의도한 의미로 이해했는지 재확인이 필요한 경우

요청이 이미 명확하거나, 잘못 추측해도 쉽게 되돌릴 수 있는 사소한 사항이면 인터뷰 없이 진행한다.

# 인터뷰 원칙

1. 이미 확인된 내용은 다시 질문하지 않는다.
2. 한 번에 최대 3개까지 질문한다.
3. 다음 질문 앞에는 지금까지 확정된 내용을 표기한다.
4. 구현 방법보다 사용자의 의도와 요구를 먼저 확인한다.
5. 사용자의 표현을 임의로 전문용어로 치환하지 않는다.
6. 추측이 필요한 경우 추측하지 말고 질문한다.
7. 질문은 가능한 한 짧고 명확하게 작성한다.
8. 선택지가 명확한 경우 선택형 질문을 우선 사용한다. 선택형 질문 도구(AskUserQuestion 등)를 쓸 수 있으면 활용한다.
9. 사용자가 자유롭게 설명해야 하는 내용은 개방형 질문을 사용한다.
10. 인터뷰 종료 전에 이해한 내용을 요약하여 사용자에게 확인한다.

# 인터뷰 절차

## 1. 모호성 분석

사용자의 의견에서 다음 항목을 찾는다.

- 명확하게 정의된 내용
- 모호한 내용
- 누락된 조건
- 해석이 여러 개인 표현
- 확인이 필요한 가정
- 기존 요구사항과 충돌할 가능성이 있는 내용

이미 명확한 항목은 질문 대상에서 제외한다.

## 2. 질문 우선순위 결정

질문은 다음 순서로 우선한다.

1. 목적
2. 핵심 요구사항
3. 동작 방식
4. 예외 상황
5. 우선순위
6. 제약조건
7. 세부 표현 및 명칭

전체 설계에 영향을 주는 질문을 먼저 한다.

## 3. 질의문 생성

질문은 가능한 경우 아래 형식을 따른다.

### 선택형

예: "배선이 다른 배선과 교차할 경우 어떤 동작을 원하시나요?"

A. 단순 교차
B. 자동 연결
C. 사용자가 선택
D. 다른 방식

### 확인형

예: "제가 이해한 내용은 '배선의 시작점과 끝점은 반드시 단자여야 한다'는 의미입니다. 맞습니까?"

### 구체화형

예: "'자유롭게 이동'이라고 하셨는데, 회전도 자유롭게 허용한다는 의미인가요?"

### 예외 확인형

예: "단자가 삭제될 경우 해당 단자에 연결된 배선은 어떻게 처리해야 하나요?"

질문이 많을 경우 한 번에 모두 제시하지 않고, 핵심 질문 1~3개를 먼저 한 뒤 답변 결과에 따라 다음 질문을 이어간다.

## 4. 답변 분석

사용자의 답변을 다음과 같이 분류한다.

- 확정
- 부분 확정
- 추가 확인 필요
- 기존 요구사항 수정
- 기존 요구사항 폐기
- 신규 요구사항

사용자의 답변으로 해결된 질문은 다시 질문하지 않는다.

## 5. 의견 재정의

인터뷰 결과를 바탕으로 사용자의 의견을 다음 형식으로 정리한다.

### 확인된 요구사항

- ...

### 수정된 이해

기존 이해:
- ...

인터뷰 결과:
- ...

### 추가된 조건

- ...

### 미확정 사항

- ...

## 6. 최종 확인

인터뷰가 충분히 진행된 경우 사용자의 의견을 짧게 재정리하고 확정 여부를 묻는다.

예:

"현재까지 이해한 내용은 다음과 같습니다.

- 배선 시작점과 끝점은 반드시 단자에 연결
- 기존 배선의 중간에는 분기점 생성 가능
- 단순 교차는 연결되지 않으며 반원으로 표시
- 분기점 생성 시 쉐도우 이미징으로 사용자에게 표시

이 내용으로 요구사항을 확정해도 되는지 확인해주세요."

# 종료 조건

다음 조건을 만족하면 인터뷰를 종료한다.

1. 핵심 요구사항이 명확하게 정의됨
2. 중요한 모호성이 제거됨
3. 구현에 영향을 주는 주요 선택사항이 확정됨
4. 사용자와 이해 내용이 일치함

사소한 세부사항 때문에 인터뷰를 불필요하게 계속하지 않는다.

# 금지 사항

- 이미 사용자가 답한 내용을 반복해서 질문하지 않는다.
- 사용자의 의견을 임의로 추가하지 않는다.
- 인터뷰를 이유로 작업 진행을 불필요하게 지연하지 않는다.
- 모든 상황에서 인터뷰를 강제로 실행하지 않는다.
- 질문 자체가 목적이 되어서는 안 된다.
